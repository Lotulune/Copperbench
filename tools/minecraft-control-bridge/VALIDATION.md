## 测试中修复与观察到的限制

1. Windows MCP 下直接使用 multiprocessing 启动输入子进程发生超时。改用专用 stdin/stdout 管道，
   工作进程不继承 MCP 输入；协议集成与异常退出测试均通过。
2. X11 游戏第一次 GUI 点击有时使用旧鼠标位置。加入默认 100 ms 的移动后等待，再次核对焦点和坐标；
   后续世界选择、保存、退出与重启菜单点击通过。
3. 自动化测试的模拟后端最初与正在运行的 X11 游戏争用桌面锁；为后端划分锁命名空间后最终 22/22 通过。
4. Windows 初始夹具的中文 IME 将普通 Tk 按键转为组合输入。仅关闭该一次性测试窗口自身的 IME 后验证物理键输入；
   游戏输入法/布局差异仍须在实际应用中观察，不修改用户全局输入设置。
5. `SendInput`/XTEST 接受事件不能证明游戏消费了事件；所以保留后续截图，失败与失焦不能自动重试。
6. 对话中的长推理会使截图过期。有效期由最初 30 秒调整为 120 秒，仍要求最近截图、窗口身份和几何一致。
   固定场景驱动每次调用前重新观察；图片判断和验收结论由主 LLM 完成。
7. 退出客户端后无法再截图，回执为 `executed_unobserved`，结合退出日志与进程消失判定正常关闭，
   不把这个状态单独当作玩法成功。

## v0.1.2 合同与操作策略修复（2026-09-22）

PRD17 实机使用确认了残留的点击 30 秒限制，虽然工具描述与普通动作检查已经写成 120 秒。v0.1.2 将两处时效检查统一为同一常量，过期错误提供帧龄及最新 frame ID；动作前的时效、焦点、几何拒绝写入 `step_rejected`。窗口几何检查也覆盖键盘批次，避免移动窗口后沿用原观察。

默认动作后补足最多 150 ms 的短刷新等待，输入已全部释放；末尾显式等待及剩余 2,000 ms 预算共同限制补足量。回执区分动作耗时、声明时长、刷新等待预算和整个步骤耗时。该等待不判断游戏界面是否就绪。

37 项测试全部通过，覆盖真实 stdio MCP/输入 worker 与模拟 OS 后端、60 秒旧图点击、超过 120 秒拒绝、等待预算、输入释放后再截图、等待期间失焦、去重、急停与父进程退出。证据为仓库 `.tmp/mcb-012-final.log`。测试不操作 Minecraft，不计为新版本桌面输入或玩法通过。

项目 `AGENTS.md`、README 和服务工具说明取消逐动作的强制 Jev 往返：明确操作直接执行，复用 `mc_step` 图片，仅在未知状态处再观察。当前连接在源码更新后仍返回旧 doctor 结构，运行中的桥未重载；未启动第二个控制器替代它。下述 PRD17 续验使用旧连接及新操作策略，不宣称新等待逻辑已经实机验证。
