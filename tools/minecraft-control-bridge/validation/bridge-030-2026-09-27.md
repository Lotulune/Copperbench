# Bridge 0.3.0 验证记录（2026-09-27）

本次修复来自 Overlord Mobs 试作：中文输入法下菜单点击/文本有效，但 e/Escape 游戏控制无响应；用户手动切换英文后恢复。旧版每个未知菜单按钮都由主模型往返，操作明显缓慢。

## 已验证

- 回归：`tools/minecraft-control-bridge/.venv/Scripts/python.exe -m unittest discover -s tools/minecraft-control-bridge/tests -v`，69 项通过。覆盖原有 MCP/worker、输入去重/释放、焦点/F8，以及新增 IME 准备/确认/恢复、创建设置/重复存档/最终界面守卫、Jev 错误和等待中急停。
- 真实 Windows IME：`tests/live_windows_ime.py --native-only`，本机中文 IME 的 open 状态在同一目标线程上 true → false → true。没有安装英文键盘或改系统默认布局。证据：`output/minecraft-validation/bridge-030-native-ime/ime-result.json`。
- 真实 Jev REST + 模拟菜单：`tests/live_jev_menu.py`。进入流程 3 次 Jev / 3 批输入，8,719.89 ms；创建流程 6 次 Jev / 6 批输入，16,545.16 ms。两者均由一次 menu_flow 完成本地流程。证据：`output/minecraft-validation/bridge-030-live-jev/result.json`。
- 新鲜进程的版本与 schema 应报告 0.3.0；MCP 默认 controller=jev、keyboard_policy=english。旧进程不会因修改文件而升级。

## 限制

- 真实桌面的全按键测试未拿到测试窗口前台焦点，正确停止；未绕过检查。失败回执保留在 `bridge-030-ime` 和 `bridge-030-ime-focused`。
- 上述 Jev 耗时基于模拟画面，不含实际 Minecraft 加载时间。没有据此宣称实机总体加速倍数。
- 新创建流程需要首次截图校准；没有把旧三视图建模任务的世界名称图片伪造为可通用模板，也未自动创建/删除用户世界进行试验。
- 当前 Codex MCP 会话运行的仍是旧 0.2.0 worker。重连后方能执行 0.3.0 新参数和真实 Minecraft 复验。
- 原模组的保存重进由用户确认，来源为用户实测；模组构建、分类页和刷怪蛋右键召唤已由旧桥录制验证。

## API 依据

- [GetKeyboardLayout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeyboardlayout)：查询目标线程的活动输入区域设置。通过 `smart-search fetch` 获取，页面标注更新日期 2024-02-22。
- [WM_INPUTLANGCHANGEREQUEST](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-inputlangchangerequest)：目标窗口可接受或拒绝输入语言请求，因此代码必须等待实际状态确认。
- Windows SDK `10.0.26100.0/um/immdev.h` 的 `IMC_SETOPENSTATUS=0x0006` 与本机真实 IME 开/关/恢复结果。该单页 Web 获取失败，未将失败抓取当作来源。
- `smart-search doctor` 的主聊天上游返回 HTTP 503；同 CLI 的官方页面 fetch 正常。没有静默切换搜索提供方。
