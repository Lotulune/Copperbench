# 阶段与发布门禁

每个阶段必须产生可重复验证证据。完成代码或展示截图不等于通过门禁。

## G0：来源与构建

- 固定 MCreator 稳定标签和 Fabric Generator 提交。
- 许可、署名、商标清理和修改记录检查通过。
- Windows 11 x64 可从干净环境使用 Java 25 完成构建和启动。Windows 10 不支持。
- 测试产物记录依赖锁定信息和源提交。

## G1：领域与兼容

- UI、MCP、headless 对同一命令得到相同领域结果。
- 单写者锁、修订冲突、事务失败和恢复点测试通过。
- 上游工作区打开后未知字段不丢失。
- A/B/C 级代表插件兼容样例通过预定行为测试。

## G2：生成器矩阵

每条受支持版本轨道运行 Fabric 与 NeoForge 的黄金工作区生成和编译测试。最低样例包含方块、物品、配方、简单过程、纹理、语言条目和资源引用。

动态最新版和前一个稳定版要求完整功能门禁；1.21.1 与 1.20.1 要求构建兼容和严重回归门禁。加载器不支持的能力必须产生明确诊断，不能静默忽略。

## G3：MCP 与 headless

- MCP 协议一致性、工具 Schema 和版本协商测试通过。
- 三档权限、受保护操作、令牌吊销、CORS、并发冲突和日志脱敏测试通过。
- `build`、`validate`、`export` headless 命令有稳定 JSON 输出和退出码。
- MCP 与 headless 不得绕过恢复点或领域校验。

## G4：产品外壳

- Playwright 覆盖核心 React 工作流，Java 集成测试覆盖 JCEF bridge。
- 视觉回归覆盖 1366×768、1920×1080、2560×1440、3840×2160，以及 125%、150%、175%、200% 显示缩放。
- 验证紧凑、标准、宽屏布局，无文本溢出、控件遮挡和不可达操作。
- 无边框窗口通过拖动、八向缩放、Snap、最小化、最大化、恢复、`Alt+Space`、多显示器和 DPI 切换测试。
- JCEF 崩溃与系统窗口框架回退测试通过。

## G5：资产与 Blockbench

- 模型、纹理、UV 和动画往返保留稳定资产标识与引用。
- 未保存资产、Blockbench 退出、版本不兼容和路径越界产生可执行诊断。
- 独立资源包覆盖、测试启动和 ZIP 导出通过黄金样例。
- 资产 MCP 不能访问当前任务范围外的路径。

## G6：版本与迁移

- 工作区版本比较、恢复点和还原在脏工作区与已有 Git 仓库中测试通过。
- Fabric/NeoForge 迁移只生成副本，并报告支持、替代、丢失和人工处理项。
- 迁移失败不修改源工作区；重复迁移结果可复现。
- 上游 MCreator 工作区迁入产生备份与迁移报告。

## G7：Windows 发行

- 安装、升级、卸载不删除用户工作区或全局插件。
- JDK、JCEF、Gradle 与本机组件打包在 Windows 11 x64 验证。
- 断网状态下可创建、编辑、生成、查看历史和运行已缓存依赖的构建。
- 安装包不请求账户，不加载 CDN，不默认发送遥测。
- 发布说明包含加载器/版本矩阵、已验证插件、已知限制、许可证与来源。

## 证据产物

每个门禁保存机器可读测试结果、关键日志、版本矩阵、UI 截图索引和失败重现命令。阶段文档必须链接对应证据，不能只写“人工测试通过”。
