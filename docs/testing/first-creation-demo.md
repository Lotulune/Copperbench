# 首作连续实机演示与证据协议

**状态：拍摄协议已准备；新连续演示、截图及玩法结果均为 `not_run`。** 本页不是演示成片或验收报告。操作入口见[首作一页路线](../user/first-creation.md#一页路线)，后续安排见[复评优化 Spec](../roadmap/review-optimization-spec-2026-10-16.md)。

目标是用同一次原生操作串起：创建独立工作区 → 主动触发安全的保存输入校验失败 → 定位与修复 → Minecraft 中取得／放置 → 新客户端打开同一世界 → 按原验收回执精确导出。普通构建、玩家观察和 GameTest 分别记录结果。

本路线的主动失败是保存输入校验拒绝。真实 Gradle 构建失败的复现、诊断与修复仍按最终包及 Agent 任务研究合同独立登记，不能由这一段结果推断。失败示例依据[方块数值范围](../../src/main/java/net/mcreator/element/types/Block.java)及[写入校验合同](../../src/main/java/dev/copperbench/core/application/BlockFieldContract.java)。

## 一条连续原生流程

原始录像从原生 Copperbench 的版本／目标工作区确认开始，连续保留创建、错误、修复、等待、游戏和导出过程。时间较长时可以另做带时间索引的剪辑版；原始录像不跳步、不用其他版本画面补帧。以下每步登记起止时间、实际输入、观察与证据路径。

| 段落 | 原生动作 | 可见结果与完成条件 |
| --- | --- | --- |
| 1. 创建 | 「新建工作区」选择 Fabric 1.21.1，名称 `First Creation`、ID `first_creation`、包名 `com.example.firstcreation`，选新空目录并确认。 | 工作区实际打开，生成器为 `fabric-1.21.1`；记录工作区身份。快捷首作按钮仅在受测包实际提供时使用。 |
| 2. 创建方块 | 「模组元素」→ 新建「方块」`trail_block`；显示名 `Trail Block`、硬度 `3`、抗性 `6`，默认立方体／`minecraft:stone`，保留方块物品；「应用更改」后回读。 | 已保存值与填写值一致。录下字段与成功状态，不把可见输入当作已保存。 |
| 3. 保存输入校验失败 | 只将硬度改为 `-2`，点击「应用更改」。这是当前源码范围 `-1..64000` 之外的输入。 | 保存被拒绝，记录真实 `FIELD_VALUE_OUT_OF_RANGE`、元素／字段路径和详情；其他草稿仍可见。若实际被保存，登记失败并先调查，不把预期拒绝写成已发生。 |
| 4. 定位修复 | 使用诊断的「定位字段」返回硬度，改回 `3`，再次应用并回读。 | 同一元素修复成功；保留原失败回执／截图。路径以实际回执为准，不能因修复成功覆盖失败尝试。 |
| 5. 准备精确导出 | 在最终构建前用顶部「更多运行选项」→「GameTest」。没有配置时，从原失败任务点「准备测试模板」，等准备任务成功。 | 记录 `copperbench-tests.json` 的真实模式与测试范围。默认 `packaged_jar` 模板只检查模组加载；准备后才冻结用于后续构建／游戏的输入。已有配置先核对，不能覆盖。 |
| 6. 构建 | 「构建」，等待新任务终态。 | `succeeded` 与 `BUILD SUCCESSFUL`、任务 ID、输入摘要一致；失败时保留原任务，按诊断修复并登记重试。 |
| 7. 游戏结果 | 经目标工作区启动客户端；新建唯一创造世界并允许命令，输入 `/give @s first_creation:trail_block 16`，确认数量／名称，选中并放置一个。 | 录下真实 Minecraft 画面、物品栏／快捷栏与放置位置；SDK 调用成功和渲染日志分别保存，不能代替玩家可见结果。 |
| 8. 同世界重开 | 保存并退出世界，再退出 Minecraft；确认原 PID 退出、日志正常及 lifecycle 任务终态。再启动新 PID，打开同一世界，检查原位置；再次正常退出并核对终态。 | 两次客户端身份和任务独立，同一个世界／位置可追踪；窗口消失不足以证明正常退出。异常或缺证项保持 failed／unverified。 |
| 9. 精确导出 | 对冻结输入运行 GameTest；在成功原任务查看「GameTest 验收报告」与「用例与被测内容」，确认 `verification.status=passed` 和被测 JAR hash，再点「导出本次已验证 JAR」。保持历史输入导出选项关闭。 | 导出任务成功，保存真实回执目录内 `verified-mod.jar`、`gametest-results.xml`、`verification.json`。分别核对 JAR、XML SHA-256 与原验收回执，不重新构建另一个 JAR 冒充被测文件。使用「交付与导出」→「打开此次精确导出目录」展示结果。 |

测试模板准备、修复或外部编辑若改变了最终输入，先重新构建并核对受影响的游戏步骤，再执行当前输入的验收／导出。缺少真实通过的打包 JAR 任务时，第 9 段为 `unverified`；普通「重新构建并导出」可以单列展示，不能作为精确导出完成。GameTest 加载检查不能证明第 7、8 段的放置或持久化，玩家确认按钮也不替代证据。

## 草稿恢复单独登记

元素草稿由[会话内 Map](../../ui-shell/src/hooks/elementEditorDrafts.ts)保存；[源码编辑器](../../ui-shell/src/components/SourceWorkbench.tsx)也使用内存会话。[未保存输入保护](../../ui-shell/src/hooks/unsavedDraftGuard.ts)用于退出提醒，不是写盘恢复服务。首作保存的工作区／任务引用不保存未提交字段或完成结论。

| 场景 | 当前边界 | 本协议的实测状态 |
| --- | --- | --- |
| 同一前端会话内切页、校验拒绝或冲突 | 草稿可跨页面保留；保存时仍核对 revision／文件 hash。 | `not_run`；由本次真实观察填写。 |
| 正常退出应用后重新启动 | 内存 Map 不提供跨进程草稿恢复；已保存工程与未保存草稿分开检查。 | `not_run`；单列退出方式、提示选择、重开后的已保存／未保存内容。 |
| 应用崩溃后重新启动 | 同会话保留不能推导崩溃恢复。 | `not_run`；单独任务和证据，不复用正常退出结果。 |
| 断电后恢复 | 同会话保留不能推导断电恢复。 | `not_run`；单独环境、任务和证据，不复用崩溃结果。 |
