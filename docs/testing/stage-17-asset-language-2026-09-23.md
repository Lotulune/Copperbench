# Stage 17 资产诊断页面中英文验证

接续[诊断总览语言切换](stage-17-language-2026-09-23.md)，本轮将中英文显示延伸到资产列表、引用详情、导入与移动审阅、加载／空白／错误状态。**这是 v30 之后的源码和浏览器验证，不是新发行包、真实 JCEF 或完整产品英文验收；PRD17 总门禁继续开放。**

## 实现与约束

[AssetBrowserView](../../ui-shell/src/components/AssetBrowserView.tsx) 的静态文案在渲染时选择语言，包括分类、资源解析状态、引用依据、索引计数、筛选、排序和审阅按钮。模块级分类和状态标签改为按当前语言计算。

资产页保存原始 `AssetProjection`，由[资产显示模型](../../ui-shell/src/types/assets.ts)在投影或语言变化时派生标签。切换语言无需重新请求资产，不清除搜索、分类或选择。资产名称、稳定 ID、路径、原始引用值、SHA-256 和外部错误原文保持原值。

通知和审阅错误保存双语文本或原始 `LocalizedText`，显示时才调用翻译。因此已经出现的成功通知、Blockbench 不可用提示及 Core 拒绝诊断可随语言变化，不重做导入或再次打开外部程序。导入／移动草稿以及既有预览失效规则保留。

英文紧凑控件保持单行，工具栏允许换行且不被纵向压缩；错误状态徽标不再挤成两行。资源详情中的长路径和哈希仍可换行读取。

## 验证

[新增浏览器测试](../../ui-shell/e2e/stage17-asset-language.spec.ts)包含六类检查，各在 `chromium` 与 `compact-1366` 执行：

1. 已加载标签随语言更新，搜索／分类／选中资产保留，记录的 `list_assets` 请求数不增加。
2. 原版已解析与外部尚未验证状态区分；键盘展开详情；原始中文 JSON Pointer、资源版本、64 位哈希和长路径保留；1280×720 与 1920×1080 无横向溢出，工具栏与卡片边界不重叠。
3. 导入和移动路径草稿保留，改动路径后仍须重新预览；导入成功后通知可切换语言。
4. 已出现的 Blockbench 不可用提示切换语言，外部打开调用计数仍为一次。
5. 返回的 Core 导入拒绝诊断切换语言，路径保留，命令计数仍为一次。
6. 无匹配结果、读取中、空资产和读取失败状态的英文提示及恢复按钮可见。

这些用例使用 MockCoreBridge／注入的桥接回执，验证 UI 呈现与交互；不证明真实磁盘导入、Blockbench 进程或 Core 资源解析本身通过。

证据保留在 `output/stage17-asset-language/`。首轮新增五用例及既有资产／一致性测试共 56 项通过。增加失败诊断用例后，一轮结果为 10 通过、2 失败：测试回执遗漏必填 `operation`，被产品协议校验拒绝；补齐测试后定向 2 项通过，再执行专项 12 项通过。没有放宽协议校验。

截图复查还发现初版工具栏换行后与卡片重叠，原横向溢出断言无法捕获；增加 `flex-shrink: 0` 和纵向边界断言后复验通过。1920→1280 缩放后另出现过内容区域空白截图，单独禁用动画仍会出现，不能确定只由入场动画导致。测试现在检查内容透明度为 1、标题在视口内，并在缩放与嵌套滚动后等待两个浏览器绘制帧，再禁用动画截图；随后定向双项目复验通过，4 张新截图均有完整资产内容。旧空白图保留，但不作为显示通过证据；英文资产显示证据以 `paint-verified/` 为准。这项浏览器截图处理不证明原生宿主不存在绘制问题。最终日志、截图和哈希清单见该目录的 `proof.json`。

## 仍未覆盖

资产页内嵌的 Blockbench 设置、建模任务与回导面板仍有中文；字段编辑器、Procedure/Blockly、任务控制台其他操作及部分桥接错误也尚未完成英文覆盖。本轮没有修改这些区域的行为，也没有将它们标为英文通过。

真实 JCEF、Windows 100%／150% 系统缩放、同一冻结候选的全流程及真实诊断采集联合验收仍待完成。既有 v30 包和游戏证据不包含本轮改动；未安装更新 Ubuntu，未提交或发布。
