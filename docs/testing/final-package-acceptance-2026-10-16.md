# 最终包验收矩阵（2026-10-16）

状态：任务准备；以下实测均 `not_run`。对应[复评 spec R03](../roadmap/review-optimization-spec-2026-10-16.md)。执行前选定精确发布资产；本轮工具修复不会自动更新既有安装包。历史记录继续绑定原包，不能移作新包通过。

## 冻结与身份

一次冻结可用于全部适用场景，不为每个场景重新打包。冻结记录必须包含：来源 URL／tag／commit、资产名称／字节数／SHA-256、安装器与 payload manifest 摘要、安装后应用 JAR／EXE／JBR 的摘要、SDK 版本、OS／桌面会话、显示缩放、缓存／网络条件和验证时间。签名后的文件须重新取 hash。包中实际文件与来源记录有差异时停止该场景，保留失败。

未发布本地候选使用 source-paths-v2 的完整源码身份，明确 dirty 状态和运行时输入；官方已发布包使用它自己的来源与资产身份。两个集合分别保留。执行前确认空间和现有包缓存，复用已核对的相同字节；不复制 JDK、完整工程缓存或用户世界作为每个场景的证据。

每次运行使用唯一 `runId`，记录 `scenarioId`、`artifactSha256`、环境、开始／结束时间、状态（passed/failed/unverified/not_run）、原因、证据文件相对路径与 SHA-256、受测进程、操作记录和操作者。失败后定向重试另建 attempt，不改写首轮日志。没有可见行为证据时保留 `unverified`。

## 操作与证据目录

图形安装／产品界面由一个 computer-use 控制器执行，遵守当前截图→动作→刷新观察的顺序；焦点不明或意外对话框时停止当前交互并记录。SDK 只负责已授权的工作区生命周期与任务调用，不充当玩家操作证据。禁止重建已移除的 Minecraft control MCP 或启动其 bridge worker。

`output/minecraft-validation/<runId>/` 保留 package-identity、source-identity、environment、actions、screenshots、logs、task-receipts、artifact-identities 与 summary。非游戏安装证据放入同一运行的 installer 子目录或独立 acceptance 目录，并由 summary 引用。保留小型原始证据和摘要，避免重复完整包／运行时／世界副本；证据中不含连接密钥或账户凭据。

退出验收须同时核对：目标客户端正常进程退出、游戏日志收尾、Copperbench 原任务的终态、workspace host 的正常关闭。只收到 stop 输入、窗口消失、SDK 请求成功或进程被强制终止均不能单独判为正常关闭。
