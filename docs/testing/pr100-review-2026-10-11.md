## Resolved findings

### P1: Native references are compared against projected names

[Fabric validation](../../src/main/java/dev/copperbench/generator/fabric/Fabric1211Generator.java)
builds `elementNames` from `WorkspaceState.Element.name`. For imported upstream
elements, [the mapper](../../src/main/java/dev/copperbench/core/workspace/mcreator/MCreatorWorkspaceStateMapper.java)
projects a CamelCase internal name such as `MyGem` to its registry name
`my_gem`. However, [the new reference validator](../../src/main/java/dev/copperbench/core/application/ElementGenerationValidation.java)
compares the native reference `CUSTOM:MyGem` against that projected-name set.

A temporary real MCreator workspace reproduces `FIELD_REFERENCE_INVALID` for
an item's `recipeRemainder`, even though the upstream workspace resolves the
target. A recipe's `recipeReturnStack` reproduces the same error. An otherwise
equivalent lowercase `my_gem` workspace has no validation issues. This also
reproduces in an items-only workspace, without introducing a recipe.

[The task gateway](../../src/main/java/dev/copperbench/generator/GradleWorkspaceTaskGateway.java)
fails the task at backend validation before source generation or Gradle starts.
Resolve native references using upstream internal identities; do not require
users to rename valid existing elements or alter their registry names. Add a
regression with different internal and registry names.

### P2: Real delivery CI does not follow production changes

[The M1 workflow](../../.github/workflows/agent-readiness-m1.yml) filters pull
requests to five gate/fixture paths. A change confined to
`VerifiedArtifactExporter.java`, `ElementFieldContract.java`,
`sdk/python/copperbench_native.py`, or the field-contract schema matches none
of them. No other workflow invokes `runAgentReadinessDelivery`, including
[Nightly](../../.github/workflows/nightly.yml).

This PR runs the real gate because it changes the gate itself. After merge,
ordinary changes to the implementation can pass the existing CI without
exercising the real build/failure/repair/accept/export/reconnect chain. Include
the production inputs of that chain in automatic selection, or provide
equivalent scheduled coverage. Keep the existing required check names.

## Fixes and verification

P1 now resolves upstream internal names by element UUID through
`MCreatorWorkspaceStateMapper.internalElementNames`, retaining the public
registry-name projection. It uses persisted element IDs when present and the
existing deterministic identity otherwise. Only currently present identities
can resolve through the snapshot; a deleted target cannot be revived by stale
metadata or by a replacement with the same projected name. Newly created
elements also resolve before the upstream snapshot is refreshed. Fabric and
NeoForge share the corrected native validation path.

The new [native-reference regression](../../src/test/java/dev/copperbench/core/workspace/mcreator/NativeElementReferenceValidationTest.java)
uses a real upstream workspace with internal name `MyGem`, registry name
`kept_registry`, item remainder and recipe input/output references. It covers
Fabric/NeoForge 1.21.1, stored/deterministic IDs, reopening, new/deleted targets,
and rejection of registry-name aliases, wrong case and missing targets. File
digests also verify that validation does not rewrite the workspace. Before the
fix, four of seven cases failed; all seven pass afterward.

P2 expands the M1 PR paths to the runtime, generator, SDK, contract and build
inputs used by real delivery. Documentation-only and ordinary UI component
changes do not select this additional workflow. Manual dispatch and existing
required check names remain unchanged. M1 protocol checks now include the new
native-reference regression; [routing tests](../../scripts/tests/test_ci_selection.py)
read the workflow's paths and check 23 positive and three negative examples.
