# Stage 17 诊断界面的中英文切换

本轮补齐 **React 总览诊断流程**的中英文切换、键盘定位和显示回归。尚未完成整个产品的英文覆盖，也未执行真实 JCEF 的 Windows 100%／150% 缩放验收；G17-B 和其他总门禁继续开放。这些源码改动晚于 v30，不属于已经归档的 v30 安装包或游戏证据。

## 实现范围

- [locale.ts](../../ui-shell/src/i18n/locale.ts) 保存会话语言，通过 `useSyncExternalStore` 通知界面更新；默认中文，`localStorage` 可用时记住选择，不可用时仍允许本次会话切换。同步更新文档 `lang`。
- [WorkbenchContext](../../ui-shell/src/context/WorkbenchContext.tsx) 的消费者订阅语言变化；切换不重新挂载编辑器，不重建工作区，不提交字段草稿。合同标识、用户名称和日志原文不经过静态文案翻译。
- 标题栏增加语言选择并将其报告为原生窗口的 `client` 区域；导航、总览健康卡、底部计数、Blockbench 总览提示及任务抽屉基本标题／关闭按钮使用对应语言。
- 英文合同消息使用现有 `LocalizedText.fallback`；类型与常见状态提供英文标签。未知扩展标识保留原值。
- 健康卡的标题与数值上下排列，窄窗口减少列数，避免长英文挤在同一行。底部诊断按钮回到总览后，将键盘焦点放到有名称的健康区域；详情中的字段／资产动作继续使用原合同目标。

## 验证与证据边界

[stage17-language.spec.ts](../../ui-shell/e2e/stage17-language.spec.ts) 使用注入的 MockCoreBridge 投影构造六类界面场景：零诊断、单元素多错误、仅资产错误、混合诊断、仅历史失败任务、索引尚未完成。它验证给定 Core 快照如何显示，**不验证 Core 如何采集和汇总真实诊断**。

两组浏览器项目分别从 1920×1080、1366×768 启动；六类场景另在 1280×720、1920×1080 检查健康卡与底部计数宽度，验证中文／英文数量一致、历史任务错误不进入当前计数、部分检查提示、键盘回到总览及刷新后的语言恢复。另验证未保存字段草稿保留、存储拒绝时仍能切换、详情字段／资产定位、原生窗口区域上报与点击不触发拖动。明暗主题各保留中英文截图，使用 1280×720 CSS 视口、1.5 浏览器像素密度。

| 检查 | 结果 | 证据 |
|---|---|---|
| 最终语言与诊断专项 | 11 用例 × 2 浏览器项目，22 通过 | `output/stage17-language/stage17-language-accepted.log`；截图 `output/stage17-language/accepted/` |
| 既有一致性与自绘窗口回归 | 5 + 11 用例 × 2 项目，32 通过 | `output/stage17-language/stage17-language-regression.log`，其中这 32 项全部通过 |
| 最终生产构建 | 中文词典门禁 384/384、TypeScript、Vite 通过；保留大包体积提示 | `output/stage17-language/stage17-language-build-accepted.log` |
| 源码、构建产物、日志、截图哈希 | 按文件归档 | `output/stage17-language/proof.json` |

初轮语言测试 7 通过、1 失败，原因为测试使用不唯一的 `status` 选择器；后续 52 项混合回归有 50 通过、2 失败，两个失败均为新测试错用了 `/properties/hardness`，实际 fixture 合同为 `/fields/hardness`。修正测试路径后，定向复验 2 通过，最终语言专项 22 通过。保留失败日志，不把重跑数相加声称全部为独立用例。没有降低产品焦点检查或修改合同以适配错误测试。

## 尚待完成

资产中心、字段编辑器、Procedure/Blockly 和任务抽屉的其他操作仍有静态中文；部分既有合同 fallback 自带中英混合文字。因此当前语言选择只代表已接入区域的语言偏好，不代表全产品英文验收通过。后续需逐项覆盖诊断目标页及异步错误状态，并检查语言切换时模块级标签和已存状态文案是否更新。

真实 JCEF／系统缩放、相同发行候选上的完整六场景、真实数据采集与 UI 的联合回放仍待验证。浏览器的 `deviceScaleFactor: 1.5` 不是 Windows 缩放设置的证据。本轮未重新冻结发行候选，未安装更新 Ubuntu，未提交或发布。
