# 阶段 1：领域边界与上游兼容基础

- 状态：已完成（2026-08-17 本机 G1 门禁通过）
- 依赖：阶段 0
- 对应门禁：G1

## 目标

把工作区操作从上游 Swing 页面行为中提取为稳定 Java 应用服务，使旧 UI、新产品外壳、MCP 和 headless 能复用同一套规则。

## 范围

- 建立 Command、Query、Event 合同与 Schema 版本策略。
- 实现工作区单写者锁、修订号、事务边界和结构化诊断。
- 为打开、保存、创建/更新/删除模组元素、生成、构建请求建立应用服务。
- 定义产品专属元数据命名空间和升级机制。
- 建立上游工作区黄金样例和未知字段保留测试。
- 实现插件兼容分类器与 A/B/C 级代表样例。
- 保留上游 UI 作为行为参考和临时验证入口。

## 不在范围

- React 正式页面接入。
- 完整 MCP 传输和权限界面。
- Fabric 功能扩展或 NeoForge 对齐。
- Loader Migration。

## 交付物

- `ui-core` Schema v0 和 Java 应用服务接口。
- 工作区锁、修订与事务测试套件。
- 上游工作区黄金样例库。
- 插件兼容等级解析器与样例插件集。
- 上游 Swing 行为到领域命令的映射清单。
- UI 团队可使用的模拟 Query/Event fixtures。

## 关键任务

1. 识别上游 UI 中直接修改 Workspace/ModElement 的路径。
2. 先为一个简单元素建立完整命令链，再扩展公共操作。
3. 所有错误转换为稳定代码、字段路径、严重程度和建议修复。
4. 用相同契约从旧 UI 测试适配器和 headless 测试适配器执行操作。
5. 验证插件事件不会绕过事务后留下部分状态。

## UI 并行工作

zcodeglm5.3 在此阶段完成创作者任务地图、信息架构和三套低成本方向原型。原型只使用模拟数据，不读取工作区文件或依赖 Java 内部类。

## 风险

- 上游 Swing 代码可能同时承担 UI 和业务规则。缓解：先加行为特征测试，再逐项提取。
- 过早设计“大一统领域模型”会拖慢进度。缓解：以阶段 3 纵向链路驱动最小合同。
- Java 插件可能直接触碰内部对象。缓解：分级兼容，无法适配的插件明确降级。

## 退出条件

- [x] G1 全部通过。
- [x] 同一元素操作从 legacy、MCP、headless 入口得到相同结果和事件。
- [x] 并发写入能稳定产生修订冲突，不损坏工作区。
- [x] 上游工作区往返保存不丢失未知字段。
- [x] UI 团队能够只使用 fixtures 完成核心流程原型。
