## 统一验收计划

1. 所有工作包交付后审查最终 diff，核对新增合同、调用方和文档一致性；冻结本轮受测源码身份。
2. 一次运行受影响 Node 工具与 Vite 服务回归、现有相关 Python 规划检查、Markdown 链接及产品状态检查；不以整棵脏工作树推导本轮全量测试范围。
3. 测试配置影响前端时运行一次 UI 生产构建、现有 UI 单元检查与受影响 Chromium smoke。若后续发现必须改 Java，改动全部完成后再统一执行对应 Gradle 检查，利用其 UI 构建依赖避免重复构建。
4. 仅对实际失败修复并定向复验；保留每次失败日志，禁止通过重试覆盖失败。浏览器 trace 仅失败保留；所选既有用例的少量截图归入本轮目录，新增回归不拍成功截图。不产生多个完整候选包、ISO 或重复性能基线。
5. 输出需求状态、命令／退出码／实际计数、源码身份与验收局限。最终包安装、真实新手、原生性能和 Minecraft 玩家行为不属于工具测试通过的推论。

涉及真实 Minecraft 运行时，严格按 [AGENTS.md](../../AGENTS.md) 执行：由主代理单一桌面控制器观察目标进程，通过既有 lifecycle／SDK 启动并维持会话，使用隔离工作区与唯一测试世界；持久化须新进程打开同一世界，确认日志与生命周期终态。记录进入 `output/minecraft-validation/`，不得恢复已移除的 Minecraft control MCP 或启动其 bridge worker。
