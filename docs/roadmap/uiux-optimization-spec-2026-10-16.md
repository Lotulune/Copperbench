# Copperbench UI/UX 优化 Spec（2026-10-16）

状态：16 项源码优化已实施，受影响自动化检查和 Windows 原生授权展示检查完成。由当前代理独立实施，未使用子代理；实现完成后集中验证，失败后仅修复和定向复验。

## 依据与范围

依据用户提供的 `Copperbench_UIUX_Audit_2026-10-16.md`，附件仅作为问题、建议与证据来源。流程参照“编写优化 spec 并实施修改”聊天：先制定合同，再实现，最后统一验证。附件固定提交和本地工作树不同，以已读取的本地源码为准，保留全部既有修改。

本轮维护现有 React/JCEF 工作台和 Java 授权窗口，不重新设计产品、不改 Minecraft 玩法、不发布或推送。基线文件、附件摘要、最终源码摘要和验证日志存于本地 `output/uiux-optimization-2026-10-16/`。其他聊天的修改不计入本轮成果。

## 需求与验收合同

| ID | 实施内容 | 验收要求 |
| --- | --- | --- |
| UX-01 | 共享弹窗栈、顶层键盘事件、背景 inert、初始/返回焦点 | 真实 React 覆盖 K01–K09；首次 Shift+Tab、summary、autofocus、嵌套 Esc、阻断弹窗、触发器卸载均正确。 |
| UX-02 | 创建回执绑定工作区、打开会话和请求；迟到结果独立反馈 | 提交 A、关闭、重开填写 B 后释放 A；B 不被清空、关闭或覆盖错误；A 结果可查；未决的同一创建不重复提交。 |
| UX-03 | 日志暂停跟随、未读计数、回到最新、查找、级别过滤和复制 | 追加输出不移动暂停的阅读位置；任务间独立保存位置；回到最新恢复跟随。 |
| UX-04 | `openTask(taskId, target)` 统一任务入口 | 最近失败按时间选取；提示、抽屉、日志、诊断和动作绑定同一任务；缺失任务显示明确状态。 |
| UX-05 | 原生 CLI 授权共用产品语言偏好和安全默认值 | 中英文标题、正文、操作说明、期限、撤销方式、EULA、按钮完整；路径和协议代码保留；取消为默认。 |
| UX-06 | 加深亮色次级文字 | 两主题支持的实际表面组合与页面 computed style 检查；普通文字对比度至少 4.5:1。 |
| UX-07 | 独立滚动条配色、10px 命中宽度、滚动边界 | 浏览器中两主题可辨，日志和弹窗滚动可达；原生 JCEF、触控板和 OS DPI 另列证据。 |
| UX-08 | 共享 Dialog/ConfirmDialog 与持久反馈入口 | 替换产品自有 `window.confirm/alert`；取消优先焦点、具体动词和对象名、统一头脚；原生文件选择器不变。 |
| UX-09 | 未取得状态不宣称连接成功 | 加载、未知、无工作区、重连等与真实投影一致；未知任务进度使用不定状态。 |
| UX-10 | 集中任务状态与色彩映射 | queued/running/succeeded/failed/cancelled 区分；取消请求不冒充已取消。 |
| UX-11 | 按工作区保存元素列表浏览状态 | 筛选、排序、布局、页码、选择与可恢复滚动位置在跨页返回后保留，工作区互不串用。 |
| UX-12 | 首作常规状态简化，技术证据渐进披露 | 主层突出下一步；输入不匹配、未确认结果、权限和原有构建/游戏/导出区分仍明确。 |
| UX-13 | 设置说明可见并关联控件 | 键盘用户直接读取帮助；保留 `aria-describedby`、输入校验和禁用原因。 |
| UX-14 | 日期显式使用应用语言和本地时区，反馈延迟翻译 | 应用/浏览器语言相反仍一致；时间保留原始值；切语言不清草稿。 |
| UX-15 | 创建类型搜索、用途、常用/最近目录 | 键盘可搜选长英文类型；目录和提交按钮在紧凑视口可达；可用性仅以 Core 提供的合同为准，不猜测支持范围。 |
| UX-16 | 诊断导航携带严重程度并展开定位 | 从其他页面点击底栏错误数，具体问题和动作可见，焦点落在对应诊断或可读状态。 |

## 实施顺序

1. 共享弹窗、确认和反馈；修复创建的会话归属，补类型目录。
2. 统一任务入口、日志阅读、状态、时间和诊断定位；保存元素列表上下文。
3. 原生授权双语、颜色/滚动条、设置说明和首作文案。
4. 完成回归用例后进行一次统一检查；仅对实际失败修正并定向复验。

## 统一验证

- UI：现有 Node 单元测试、i18n、TypeScript 和生产构建；受影响 Playwright 回归及新增审计用例，使用真实 React 渲染。
- Java：相关授权窗口和语言偏好测试；复用 Gradle 的 UI 构建依赖，避免重复完整构建。
- 布局：中文/英文 × 亮/暗 × 1920×1080、1366×768、1280×720，检查跟随系统；使用缩小 CSS 视口模拟 125/150/200% 内容空间并明确它不等同原生 DPI 测试。
- 保存失败、桥接错误、延迟回执、缺失任务、取消和草稿返回以既有 fixture 注入；这证明 UI 行为，不替代真实 Core、安装器或 Minecraft 验收。
- 本轮不变更玩法和世界持久化。原生 JCEF、实际 CLI 授权、跨 OS/输入设备若环境不可达，分别标为未验证，不以浏览器通过代替。

## 完成记录

详见[验收报告](../testing/uiux-optimization-2026-10-16.md)。UI 单测 67 项、相关 Java 测试 10 项、生产构建通过。Chromium 首轮 118 项中 115 项通过；修正显式回退焦点优先级和旧按钮文案断言后，27 项定向复验全部通过，原失败日志保留。创建用例的另一次失败伴随 Vite 依赖重载，同一源码定向复验通过。

新增 41 个浏览器用例覆盖审计问题与布局矩阵；24 组中英文、明暗主题、基础和缩放内容视口检查通过。真实 Windows Swing 授权展示夹具检查了双语长说明、默认取消、Tab 和 Escape；没有签发真实授权。首次观察发现长文本布局不足，已添加有高度约束的滚动区域，并通过 Java 复验和实窗观察。

原生 Linux/JCEF、操作系统 125/150/200% DPI、触控板、屏幕阅读器，以及最终安装包/真实 CLI 签发/EULA 接受链仍未验证；这些不计入本轮通过结论。未改 Minecraft 玩法或世界持久化，因此未启动 Minecraft 验收。
