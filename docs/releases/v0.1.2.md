# Copperbench 0.1.2 — maintenance release

Model imports now keep the modeling-task panel open while the asset index refreshes, so creators can continue directly to model binding. Clipboard feedback reports success only after the write succeeds and explains failures. Current setup and capability documentation has been aligned with Windows and Ubuntu support and the 37-type Java element catalog.

Asset reads, references, diagnostics and health projections now share an internal service. Public MCP/SDK contracts, workspace formats, revision checks and recovery behavior are unchanged.

## Verification

The maintenance source passed 928 Java tests (59 conditional skips), Javadoc, 196 full Chromium cases, 74 targeted two-size UI checks, 29 UI-Core contract tests and 8 MCP conformance checks. A real JCEF replay completed model import, binding and refresh without reopening the panel, then verified binding after reopening the disk-backed workspace. These results are development evidence, separate from release-package acceptance.

Package-specific source commits, checksums, installed acceptance and publication state are recorded in [the release report](../testing/maintenance-release-0.1.2.md). No test result implies unlisted Minecraft gameplay acceptance.

## Supported scope

- Windows 11 x64; Ubuntu 24.04 LTS x86_64 with GNOME Wayland/Xorg. Other Linux distributions and architectures are not certified.
- Fabric and NeoForge 26.2, 26.1.2, 1.21.1 and 1.20.1 remain the supported generator tracks; capabilities vary by loader/version.
- Windows packages are not Authenticode signed. First builds require network access; offline use depends on a verified dependency cache.
- Blockbench remains a separate installation. External-user trials, physical screen-reader certification, cold-cache/default-network certification and unlisted gameplay are outside this maintenance release's claims.
