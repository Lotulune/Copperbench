# Copperbench 0.1.1 — Windows stable

This release includes the Stage 17 consistency and authoring improvements and the English workbench. Language changes preserve editor drafts and persist in the desktop application.

- Workspace diagnostic totals, resource resolution and refresh state now agree across the overview, asset browser and status bar.
- Recovered task history retains logs and distinguishes historical observations from newly verified artifacts.
- Procedure editors use the backend trigger catalog and preserve unsupported or invalid draft connections for diagnosis and repair.
- Blockbench modeling tasks make import, element binding and runtime verification separate, visible steps.
- Generator-specific element defaults, persistence and nested field validation have broader regression coverage.

## Download and verify

Windows 11 x64 is supported; Windows 10 and macOS are not. The release contains EXE, portable ZIP, MSIX, `SHA256SUMS.txt`, `RELEASE-METADATA.json`, `product-status.json`, SPDX SBOM, licenses and third-party notices. The signed Git tag identifies the source; the Windows executables have no Authenticode signature, so Windows may show SmartScreen warnings. Verify asset hashes and GitHub provenance before installation.

Linux has a separate release tag and independent exact-binary acceptance. Its target is Ubuntu 24.04 LTS x86_64, GNOME Wayland/Xorg, with installed-runtime coverage for Fabric and NeoForge 1.21.1. Other distributions and architectures are not certified.

## Scope and limitations

The supported generator matrix includes Fabric/NeoForge 26.2, 26.1.2, 1.21.1 and 1.20.1; exact capability, preview and plugin boundaries remain in the bundled product status and documentation. First builds need network access to dependency repositories; offline builds require an already verified cache. Blockbench and its community MCP plugin are external installations. Experimental extension APIs remain experimental.

This stable distribution does not expand the existing exclusions for physical screen-reader certification, final clean Windows RC replay, external-tester certification, or Linux cold-cache/default-network certification. Historical development acceptance is identified separately from release CI and package provenance. User data, credentials, project text and raw logs are not translated by the interface.
