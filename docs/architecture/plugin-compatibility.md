# 上游插件兼容架构

兼容目标是让原版 MCreator 生态尽可能可用，同时诚实表达新 UI 无法原样承载所有 Swing 扩展。

## 兼容等级

| 等级 | 插件类型 | 首期承诺 |
| --- | --- | --- |
| A | 生成器、模板、Blockly、数据列表、语言、主题资源 | 通过兼容测试后完整支持；新 UI 主题不继承上游 Swing 主题 |
| B | 不直接依赖上游 Swing 结构的 Java 逻辑插件 | 通过 Java 兼容 API 和事件适配运行 |
| C | 注入工作区标签、菜单、偏好页或其他 Swing 组件的 Java 插件 | 在独立旧版插件界面中尽力兼容 |
| X | 依赖内部未公开字段、固定组件层级或已移除 API 的插件 | 拒绝加载或标记不兼容 |

## 版本识别

产品保留其基础 MCreator 稳定标签和内部版本标识。兼容解析器根据插件的 `supportedversions`、产品基础版本、测试清单和已知阻断规则决定状态，不伪装成任意官方版本。

插件管理器显示：插件版本、来源、目标 MCreator 版本、兼容等级、是否含 Java 代码、签名或哈希、已知限制和最后测试的产品版本。

## Java 插件信任

- 默认禁用 Java 插件。
- 首次启用或版本哈希变化时必须重新确认。
- 确认界面明确说明 Java 插件可读取或修改本机文件、联网和启动进程。
- MCP `Read Only` 或 `Workspace` 不能限制已加载 Java 插件的 JVM 权限。
- AI/MCP 不得代替用户启用 Java 插件。

## 旧版插件界面

旧版插件界面由 Java 宿主创建独立 Swing 窗口，提供必要的上游 UI 服务适配。该窗口不嵌入 React DOM，也不继承产品外壳视觉承诺。

关闭旧版窗口不能卸载插件领域能力；插件卸载仍按上游生命周期处理。无法安全初始化 UI 的插件应降级为逻辑功能或拒绝加载，不允许使主窗口无法启动。

## 兼容测试

- 建立代表 A/B/C 级插件的固定样例集。
- 每次吸收上游版本时运行安装、启动、打开工作区、执行功能、关闭和升级测试。
- 测试未知字段保留、插件移除后的诊断、缺少生成器时的只读打开，以及 Java 插件异常隔离。
- 发布说明列出已验证插件，不使用“兼容所有 MCreator 插件”的表述。
