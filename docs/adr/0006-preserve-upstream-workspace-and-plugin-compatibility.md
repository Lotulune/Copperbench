# ADR-0006：保留上游工作区与插件兼容性

- 状态：已接受
- 日期：2026-08-16

## 决定

产品应能打开或迁移正常的上游 MCreator 工作区，并尽量保持上游插件 API 与插件包兼容。迁移后允许写入本产品专属元数据，因此不承诺工作区能无损返回任意旧版官方 MCreator。

兼容性通过版本声明、自动化契约测试和已验证插件清单表达；不能把未经测试的第三方插件标记为“完全兼容”。

插件兼容分为三级：生成器、模板、Blockly 与数据类插件以完整兼容为目标；不直接依赖上游 Swing 结构的 Java 逻辑插件通过兼容 API 运行；直接注入 Swing 标签、菜单或偏好页的插件只在旧版插件界面中尽力兼容，不承诺融入新产品外壳。

Java 插件保持默认禁用。启用属于受保护操作，必须提示插件拥有完整本机代码执行能力，且该能力不受 MCP 权限档位约束。

## 原因

用户需要继承 MCreator 现有生态，而产品新增的 MCP 权限、资产版本和迁移元数据又无法永远受限于上游格式。单向可迁入、尽量可互操作比虚假的无损双向承诺更诚实。

## 后果

- 打开上游工作区前需要备份或恢复点，并生成迁移报告。
- 产品专属字段必须有命名空间和版本号，未知字段不得被静默删除。
- 上游版本更新必须运行工作区与插件兼容测试。
- 插件管理器必须显示兼容级别、目标上游版本、Java 代码信任状态和已知限制。
