# 构建失败、恢复与导出

[English](build-and-export.en.md) · [第一件作品](first-creation.md)

0.1.6 的「交付与导出」和「重新构建并导出」衔接既有构建／导出流程；旧包使用原入口。精确已验证导出仍需真实打包 JAR 验收任务，版本号或普通构建成功不等于验收通过。范围见[当前状态](../status.md)。

## 修复失败任务

1. 打开失败的原任务，查看第一条结构化诊断和相关日志，保留诊断码、路径和原始详情。
2. 字段错误用诊断入口定位控件，修正后保存；引用／纹理问题进入相关资产操作。无法映射的路径仍按原文显示，不按文件名猜元素。
3. 编译错误使用任务实际提供的源码路径／所属元素；有源码入口时打开它。手写文件在「源码」编辑，生成文件保持只读，回到其元素或生成器修复。
4. 下载失败查看日志中的依赖地址，检查所选镜像、网络与磁盘，再显式重试。首次构建会下载依赖，暖缓存成功不代表冷缓存／离线通过。
5. 保存后再次构建，直到这个新任务成功结束。先前失败的回执保留，不能因后续修复而改成通过。

保存失败／冲突时，其他草稿仍是未保存输入。先查看较新的工作区／磁盘内容，再明确选择重读或按已有规则修正；不要覆盖更新的字节。连接中断只表示暂时无法观察状态：恢复后读取原任务，不自动再启动一遍。请求取消也要等实际 `cancelled` 终态；关闭日志或停止等待不是取消。

## 普通构建导出

1. 打开「交付与导出」，核对工作区相对输出路径。默认放入 `build/libs/copperbench-delivery-<请求 UUID>/` 下，以规范化工作区名称命名；模组是 `.jar`，资源包是 `.zip`。可填写相同类型的工作区相对路径。
2. 点击「重新构建并导出」。这是一个新构建／导出任务，受理不等于成功；失败时回到原任务诊断。
3. 成功后，「打开构建输出文件夹」会打开 `build/libs`，默认交付可按本次输出路径在其中查找。自定义目标可能位于该目录之外，请从工作区根目录沿已选择的完整相对路径查找。保留本次任务和路径，避免只按修改时间挑选其他 JAR。

自定义路径须位于工作区内。已有文件仅在Copperbench记录为以往交付、且内容仍与该交付回执一致时才可替换；其他已有文件或被外部修改的交付文件会保留，请改用新路径。源码／资源目录（如 `src`、`elements`、`assets`）、依赖目录（如 `gradle`、`lib`、`libs`）以及工作区元数据／运行目录不可作为目标。`build/libs` 可用于交付，但其中无关的旧JAR仍受保护。目标正是本次构建声明的实际归档文件时，可直接使用该文件。

普通导出不继承自动验收标识。保存、编译、玩家行为确认和 JAR 验收分别说明自己的结果；资源包准备也不等于客户端已启动。

外部修改文件后，点击「重读输入与原任务」。输入已变化时，原导出成功仍保留，但应重新构建并导出最新内容。运行期间输入变化或输入无法核对时，窗口显示变化／待确认及下一步；输入核对失败不会阻止普通导出，原因保留在原任务日志中。

## 精确导出已验收 JAR

已有 `state=succeeded`、`verification.status=passed` 的打包 JAR 验收任务时，在任务面板选中它，使用「导出本次已验证 JAR」。后端核对被验收 JAR、XML 报告与当前工程输入 hash，成功后回执给出导出目录；目录包含 `verified-mod.jar`、`gametest-results.xml` 和 `verification.json`。

输入已变化时默认拒绝。确实交付旧输入时才明确选择历史导出，回执会标为历史；不能将其描述为当前输入已经通过。文件丢失／hash 变化时保留诊断，重新验收或查明原因，不用普通导出替代“精确已验证”结果。验收只覆盖报告中的用例，不隐含完整游戏玩法通过。

有「打开此次精确导出目录」时使用该按钮；它绑定这次导出任务的真实回执，不接受任意目录路径。较旧界面可按回执中的导出目录打开文件。

精确导出卡片与原任务显示该回执记录的加载器、Minecraft 和加载器版本。历史产物的兼容范围按其回执读取；缺少的项目显示「回执未记录」，不会借用当前工程的版本。

## 玩家确认与继续创作

按[首作教程](first-creation.md#4-启动-minecraft-并确认作品)实际取得／放置方块，正常退出后再启动新客户端进程打开同世界。首作引导的确认只在本会话、对应输入／元素／构建内有效；保存修改或新启动后需重新复核，不能当作长期保存的自动报告。

继续编辑时保留手写源码和未知插件字段；需要扩展复杂行为可从「源码」或 [Agent 接入](../ai/getting-started.md)继续同一工程。新输入重新保存、构建和检查，已有历史回执仍保留原适用范围。
