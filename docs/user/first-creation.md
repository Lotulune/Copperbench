# 第一件作品：在游戏里放下步道方块

[English](first-creation.en.md) · [安装](getting-started.md) · [构建失败与导出](build-and-export.md)


本页是专业模式手动路线。简洁模式请使用[对话创作路线](simple-creation.md)。
目标：在 Minecraft 中取得 16 个 **Trail Block**，放置一个，正常退出客户端后用**新的客户端进程**打开同一个世界，确认方块仍在；最后导出 JAR。本教程使用 **Fabric 1.21.1** 和内置石头纹理，不需要图片、Blockbench 或 Java。

本教程同时提供首作引导和手动操作路径；安装版本没有某个引导控件时，可沿普通新建、方块编辑、构建和客户端入口完成。各平台发布版本与包级验收见[当前下载](../releases/current.md)，源码能力见[状态总览](../status.md)。Agent 的同一作品例子在[公开 API 指南](../ai/trail-block.md)，不是本页前提。

0.1.15 新用户默认进入「简洁创作」。本页的手动教程使用可视化编辑器，请先在顶部切换「专业工作台」；也可在简洁模式选择已配置的本机 CLI，通过对话创作。

## 1. 创建独立工作区

若首次启动出现带遮罩的引导，选择「开始创作」，核对预设并选择新的空目录，确认创建。若安装版本没有该引导，或已跳过／结束引导，通过「新建工作区」手动填写：

| 输入 | 值 |
| --- | --- |
| 生成器 | `Fabric 1.21.1`（ID：`fabric-1.21.1`） |
| 模组名称 | `First Creation` |
| 模组 ID | `first_creation` |
| Java 包名 | `com.example.firstcreation` |
| 工作区目录 | 一个新的空目录，例如 Windows 的 `D:\CopperbenchWorkspaces\first_creation`，或 Linux 的 `/home/你的用户名/CopperbenchWorkspaces/first_creation` |

点击创建并确认。预期：新窗口打开工作区，活动生成器为 Fabric 1.21.1。生成器列表没有这一项时，先检查安装版本和插件，不要改选资源包生成器继续照抄。

通过首启引导创建的工作区会承接本次引导。进入编辑器或任务后，可用临时的「继续引导」返回；关闭或跳过即结束，后续打开应用不会再次弹出。这条引导路径不在已有工作区的总览和侧栏放置首作或打开工作区卡片。引导曾记录的元素被删除时，不会自动重建。

## 2. 创建并保存方块

进入「模组元素」，点击新建，选择「方块」，内部标识符填 `trail_block`，提交创建。

预期：元素列表出现 `trail_block`，可以打开它的编辑器。内部标识符决定游戏注册名；显示名称只决定玩家看到的文字。

| 编辑器字段 | 值 |
| --- | --- |
| 显示名称（`displayName`） | `Trail Block` |
| 硬度（`hardness`） | `3` |
| 爆炸抗性（`resistance`） | `6` |
| 模型与纹理 | 保留默认普通立方体和内置石头纹理（`minecraft:stone`） |
| 方块物品（`hasBlockItem`） | 保持开启 |

点击「应用更改」。预期：编辑器显示已保存；重新选择这个元素，名称、硬度和抗性仍是上述值。

引导中的保存检查会回读实际元素值；画面里仍显示输入，不等于已保存。名称已存在时打开已有元素，避免重复创建。

## 3. 构建

运行「构建」，等待任务进入成功终态。首次运行会下载 Gradle、加载器和 Minecraft 依赖，下载日志持续变化时继续等待。

预期：任务成功，Gradle 日志包含 `BUILD SUCCESSFUL`。如果失败，打开该任务的诊断和日志，按下表修复后重新构建。不要仅凭“已保存”进入下一步。

## 4. 启动 Minecraft 并确认作品

1. 在顶部运行入口选择客户端并启动，等待 **Minecraft 1.21.1** 主菜单出现。
2. 创建新世界，名称用 `CB_FirstCreation_20261014`（可换成当天日期或增加编号），模式选「创造」，开启作弊／允许命令。
3. 进入世界，按 `T` 打开聊天栏，输入 `/give @s first_creation:trail_block 16` 并回车。
4. 预期：获得 16 个 `Trail Block`。打开物品栏，将其放入快捷栏并选中；对地面右键放置一个。预期：地面出现石头外观的方块，快捷栏物品提示是 `Trail Block`。
5. 记住位置，保存并退出到主菜单，再**退出 Minecraft**。回到 Copperbench，等待这次客户端任务成功结束；若仍运行或失败，先看最后日志处理退出问题。
6. 再次从 Copperbench 启动客户端，这是一个**新进程**。打开先前的**同一个世界**，不要另建世界；确认方块仍在原处。
7. 再保存、退出 Minecraft，等待第二次客户端任务成功结束。若首作引导提供确认按钮，再确认已经取得／放置，并在新客户端中重开同世界看到方块。

保存、构建成功、客户端启动、玩家取得／放置、跨进程持久化是独立结果。引导中的玩家确认只对本会话、所选元素和对应输入／构建有效。外部修改文件后，使用引导中的「检查任务状态」核对：任务仍可能成功，但输入已变化时需要重新构建或运行；旧任务没有输入记录时显示待确认。运行期间输入变化也需要重新核对。玩家确认不是自动验收报告。

## 5. 导出与继续创作

有「交付与导出」时，核对工作区相对输出路径，点击「重新构建并导出」。任务成功后打开构建目录，找到这次导出路径对应的 JAR。没有该入口的旧包使用原有构建／导出功能。完整步骤见[构建失败与导出](build-and-export.md)。

普通导出证明构建并复制了产物；玩家确认描述你实际观察的行为。只有真实打包 JAR 验收任务通过后，才从任务面板使用「导出本次已验证 JAR」获取与报告 hash 一致的文件。这三个结果分别保存，不能互相替代。

## 6. 常见阻塞与修复

| 现象 | 下一步 |
| --- | --- |
| 字段错误／保存失败 | 按诊断定位字段，修正后再保存；其他未保存输入保留。无法定位的诊断保留原路径，可展开原始详情。 |
| 名称已存在 | 打开已有的 `trail_block` 编辑，不再创建同名元素。 |
| 外部修改冲突 | 先查看最新内容与差异，明确选择重读；不要把旧草稿当作已经保存。 |
| 构建下载失败 | 在任务日志中找到失败的依赖地址，检查网络／镜像配置，按[故障排查](troubleshooting.md)重试。 |
| `/give` 提示无权限 | 确认当前新世界已开启作弊／允许命令。 |
| `/give` 提示未知物品 | 核对模组 ID、元素内部名称；确认构建成功，并从这个 Copperbench 工作区重新启动客户端。 |
| 方块显示黑紫贴图 | 检查纹理是否仍为 `minecraft:stone`，保存、构建并重启客户端。 |
| 客户端已关闭但任务仍运行或失败 | 查看任务最后日志和退出状态，先处理退出问题再判定本次流程完成。 |

历史输入检查范围见[2026-10-14 记录](../testing/first-success-2026-10-14.md)，不代表新增引导或本次游戏步骤已经验收。当前平台包的证据范围以[当前下载中的发布记录](../releases/current.md)为准。
