# 简洁创作

[English](simple-creation.en.md) · [安装](getting-started.md) · [专业模式手动首作](first-creation.md)

简洁创作把同一工作区中的作品内容、对话、纹理预览和常用设置集中到一个界面。标题栏可随时切换到专业工作台；源码、Python 编辑器草稿和正在进行的助手任务不会因为切换而丢失。

## 开始一件作品

选择“新建作品”，填写名称并确认 Minecraft 版本和加载器。默认推荐现有首作流程使用的组合；加入已有整合包时，应选择与整合包一致的目标。模组标识和 Java 包名会自动生成，也可在“更多设置”中修改。新建使用现有工作区创建流程，不覆盖已有目录。

已有工程可通过“打开作品”选择 `.mcreator` 文件。作品在原工程上继续编辑。

未完成的新建表单会保留输入。创建成功后，可以点击“新建另一件作品”，或离开表单后再次选择“新建作品”，开始新的创建。

## 连接创作助手

可选择本机的 Codex CLI、Claude Code、Grok Build、Google Antigravity CLI 或 DeepSeek Harness。各助手名称前有品牌图标。每个对话固定使用一个后端；换后端会创建新的对话，原对话保留。

从输入框上方打开“安装与连接助手”，可以查看五种程序的安装状态、版本、路径和检测错误。选择操作系统，复制安装命令到系统终端执行，或打开官方指南。Codex 和 DeepSeek 的 npm 安装需要先安装 Node.js；Antigravity 按官方页面选择系统安装方式。安装后点击“重新检测全部”，仍未发现时重启 Copperbench 以读取新的 PATH。应用不会自动安装或修改全局 CLI 配置。

“重新检测”只检查安装及版本。“检查 CLI 连接”在独立临时目录完成协议握手，不创建创作会话、不请求模型、不批准工具操作。Antigravity 没有该独立握手接口。安装成功、协议通道可用、最近一次模型请求成功和当前执行失败分别呈现；认证状态未知时不会显示“已登录”。只有一次实际成功回复才证明当次模型配置可用。

登录入口打开该 CLI 自己的流程。Claude Code 直接运行主机程序，沿用用户的源和凭据。首次选择会优先推荐已检测到的助手；已有会话绑定和显式偏好优先。刷新状态不会重新登录或重新发送请求。

输入框底部可直接选择模型，支持搜索、刷新和输入模型 ID。Codex、Grok、DeepSeek 与 Antigravity 从各自 CLI 读取目录；Claude 自定义源从该源的模型接口读取，因此可以选择源提供的其他品牌模型。目录读取失败时会显示原因，也可以输入已知模型 ID。每个对话绑定所选模型；切换模型会新建对话并转移未发送草稿，历史对话保留原选择。选择只作用于该对话，不改写全局 CLI 配置。

DeepSeek Harness 使用官方 `dsh` 命令和本机已有配置。首次使用可按[官方指南](https://github.com/deepseek-ai/deepseek-harness)运行 `dsh web`，在 Settings → Models 中配置模型；应用中的“配置指南”会打开官方说明。它支持在对话中审批操作、停止任务，并在再次发送消息时恢复原生会话。

Antigravity 沿用它的权限设置。其非交互接口不能在对话中回传实时审批，未被允许的命令可能被拒绝；界面保留原因和处理指引，配置好所需权限后可重试。其他后端根据实际请求显示审批选项或澄清问题。

澄清问题按助手提供的类型显示单选或多选；支持自定义回答时，可填写“其他回答”。选好后点击“提交回答”。操作审批仍由相应的允许或拒绝按钮处理。

## 模型、思考强度和附件

模型菜单始终有“手动输入模型 ID”，列表加载中或读取失败时也能填写想使用的模型。填写当前源的完整 ID，再点“使用模型”。DSH 的目录会保留提供方信息；重名模型需选完整 ID。手动输入仍须被对应 CLI 和上游服务接受。

模型右侧提供 `low`、`medium`、`high`、`xhigh`、`max`。请按所选模型支持的范围选择，并非每个模型都支持全部档位；CLI 或当前源可能拒绝或调整请求强度。应用按所选值传递，不自行换档。强度随对话保存，改动从下一条消息生效。

点击回形针、拖入文件，或在输入框粘贴图片。附件先进入草稿，可查看图片缩略图、文件名和大小，也可移除；点击发送才交给助手。每条消息最多 8 个文件、合计 20 MiB，单文件最多 10 MiB；PNG、JPEG、GIF 图片单张最多 5 MiB、2,400 万像素。切换模型会一起转移草稿附件。

文件复制到工作区 `.copperbench/agent-chat/attachments/`，原文件随后移动不会影响已发送的副本。普通文件以副本路径交给 CLI 读取；Codex 和 Claude 接收原生图片内容，Grok 与 DSH 仅在握手声明图片能力时接收图片。Antigravity 当前流式接口仅支持文本，添加图片后须移除图片或换助手，不能通过传路径冒充图片输入。上传或能力检查失败时会显示原因，尚未发送的草稿保留。

“默认权限”沿用 CLI 的审批规则，需要批准的操作显示在对话中。“自动批准”需明确确认，仅作用于当前应用内对话；Codex 同时取消工作区沙箱，Claude、Grok、Antigravity 使用各自的会话参数，DSH 仅自动同意其发来的单次操作请求。源或系统的限制仍然有效。切换模型或助手新建对话时恢复默认权限，不写入全局配置。

## 创作、试玩和导出

描述想添加或修改的内容。助手通过当前桌面工作区的公共 SDK 读取实际生成器和字段合同，修改后执行构建并读取任务结果。对话展示进展；操作详情可展开查看。

右侧使用作品的真实纹理和设置，不是游戏内画面的替代。需要查看实际玩法时点击“在游戏中试玩”；“导出模组”沿用已有交付流程。构建通过不能替代游戏验证。

若专业工作台仍有未保存修改，试玩前会让你选择取消并应用修改，或试玩已保存内容。已移除内容留下的未应用设置会提供单独的丢弃入口，不影响其他内容的草稿。

“停止”中断助手执行并保留已发生的修改。已有工作区任务可在任务面板中查看和处理。“恢复点”打开项目原有历史流程，恢复范围及确认步骤与专业工作台一致。

## 离开和回来

最小化和模式切换不会停止助手。存在未结束的助手任务或未保存草稿时，退出会要求确认。关闭后保存对话记录并停止所属 CLI 进程；再次打开不会自动恢复执行，发送新消息后才继续。

未发送的聊天输入也属于未保存草稿。确认放弃并关闭后，这些文字不会保留。

对话记录保存在工作区的 `.copperbench/agent-chat/`。CLI 的原生会话记录和账号配置仍由各自工具管理。浏览器预览不具备执行主机 CLI 的能力。

## 动画教程与第一件作品

简洁界面标题栏的“快速教程”会逐步高亮真实控件。“帮助”中可以重看当前模式的教程，并阅读完整首作路线。专业模式也有对应的教程。使用“上一步”“下一步”移动，Escape 或关闭按钮退出；系统启用减少动画时保留简短淡入反馈。

1. **准备助手**：安装并配置一个本机 CLI。协议检查的验证范围见上文，实际模型响应以对话为准。
2. **新建作品**：在“新建作品”填写名称和新的空目录，选择 Fabric 1.21.1。创建后核对工作区名称和生成器。
3. **输入需求**：发送下方示例。审阅实际审批与澄清问题，不依赖模型逐字输出固定回答。
4. **审阅与保存**：在“作品内容”选择 Trail Block，检查实际元素、硬度和纹理；专业模式可查看全部字段。确认修改已应用。
5. **构建**：打开“查看进度”，检查构建任务的成功终态与产物。`accepted` 仅代表任务受理。
6. **失败恢复**：读取具体诊断，修复登录/模型配置、字段或构建问题。继续前核对已有任务，修复后读取新任务结果，避免重复操作。
7. **试玩**：点击“在游戏中试玩”，创建唯一命名的独立测试世界，获得并放置方块，核对外观和属性。
8. **持久化**：正常退出客户端，等待任务结束；重新启动新客户端进程，打开同一世界，核对方块和物品仍存在。
9. **导出与继续**：用“导出模组”检查实际构建产物与目标位置。退出并重开作品，选择原对话，明确发送后继续。

示例需求：

> 在当前工作区创建一个名为 Trail Block 的普通方块，使用内置石头纹理，硬度 3、抗性 6，并提供对应方块物品。请先检查当前生成器和可用字段，通过公共 SDK 保存并构建，告诉我实际结果及下一步如何试玩。

字段以当前生成器合同为准。对话回复、实际保存、构建成功、游戏核对和导出文件是五种分别核查的结果。首作安装包验收状态见[本次优化验证记录](../testing/simple-mode-onboarding.md)。

## 阅读与整理对话

助手回复支持标题、列表、强调、链接和代码块。代码块与整条消息可以复制；复制失败会显示可操作提示。链接只允许 HTTP/HTTPS，并通过桌面外部浏览器打开；不执行消息中的 HTML 或脚本。向上阅读时不会被新输出拉回底部。

从侧栏“整理对话记录”查看容量、导出或删除会话。导出包含助手、模型、思考强度、权限选择、时间、标题、消息及附件元数据（不包含附件文件本体），不包含原生会话恢复标识和 CLI 配置；已知凭据字段会脱敏，分享前仍需检查对话中的个人内容。导出保存到当前工作区 `.copperbench/agent-chat/exports/`，成功后显示位置。

删除需要确认，删除 Copperbench 记录和不再被其他会话引用的附件副本；若所选对话有未发送的文字或附件，确认框会说明它们也将删除。只有历史删除成功后才会清理相应草稿，失败或取消时保留输入。作品、恢复点和 CLI 原生历史保持不变。活动会话要先停止并等待收尾。容量限制为 100 个会话和 16 MiB，达到 90% 时提示整理。写入超出预算时保留旧文件和当前内存记录，整理成功后可以继续。

已有文件超过读取上限或损坏时，不会自动覆盖。“备份并重新开始”先在同目录创建唯一命名的原始备份并逐字节校验，再创建空历史；原始备份可能含敏感信息。权限或磁盘写入失败需修复相应问题后重试。
