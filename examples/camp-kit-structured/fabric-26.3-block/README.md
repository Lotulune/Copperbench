# Fabric 26.3 structured block slice

This sample supplies independent test-host source and resources. The block is created and edited through the Native API by [structured_263_block_delivery.py](../../../sdk/python/structured_263_block_delivery.py), then generated by the Fabric 26.3 plugin. No handwritten block implementation is copied into the workspace.

The [manifest](required-cases.json) freezes T10/T11 under `camp-kit-block-v1`, minimum 2, SHA-256 `a5f1def54659cbe4feabf5e8ba6554e996689e9359e750a998fd8a106ac51e2b`. These two distinct business cases do not replace the six-case Native or thirteen-case scoped-support gates.

| Input | Meaning and bounds |
| --- | --- |
| `name` | Internal identifier, immutable after creation. |
| `displayName` | Generated block language entry. |
| `description` | Persisted creator metadata. |
| `texture` | `minecraft:stone`, `minecraft:oak_log`, `minecraft:cobblestone`, or `minecraft:iron_block`; default stone. |
| `hardness` | Number -1–64000; default 0. |
| `resistance` | Number 0–2147483647; default 0. |
| `rotationMode` | 0 for no rotation or 5 for pillar axis X/Y/Z; default 0. |
| `maxStackSize` | Integer 1–99; default 64. A block item is always generated. |
| `rarity` | `COMMON`, `UNCOMMON`, `RARE`, `EPIC`; default COMMON. |

Discover the existing block contract with `get_mod_element_editor` and `{"elementType":"block"}`; read `data.fieldContract`. Negotiate `preview_targets/1` and opt in for each product session before creating or updating. Unsupported active features such as an inventory or world generation are rejected. Structured loot-table elements remain outside this slice.

[T10](src/gametest/java/copperbench/acceptance/AcceptanceTests.java) evaluates actual block drops, rejects an unknown item through Minecraft's registry-aware loot codec, writes a controlled datapack and awaits the real server resource reload. Drops change from the block item to a stick. T11 places the block through GameTest, changes axis state and saves a Z-axis block at a fixed location. A new server process reads a byte-for-byte copy of this task's saved world using the same packaged JAR; it reads the saved state without replacing it, then T10 reloads the drop to paper. The copied-world hash manifest, both XML reports and persistence receipts are retained.

From the repository root on Windows:

```powershell
pwsh -NoProfile -File scripts/run-gradle-external.ps1 runStructured263BlockDelivery '-Pp263Generator=fabric-26.3' '-Pp263GradleHome=C:/Users/Administrator/.gradle' --no-daemon --console=plain
```

The runner creates an isolated workspace and temporary task authority, then revokes that authority. Evidence is written under `output/p263-16/native`. It uses a qualified dependency cache. Installed-product and player-input/rendering acceptance belongs to the platform tickets.
